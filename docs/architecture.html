Target architecture

not built
end-to-end loop

What a systematic volatility trading system looks like end to end: data → forecasting → strategy → portfolio risk → execution → reconciliation → monitoring → research feedback.

This is a target, not a description of the box. Most of the right-hand side does not exist. There is no order manager, no broker adapter, no ledger, no reconciliation, and no portfolio risk engine — see Not built. What runs today is the left and middle: ingest, the warehouse, and the pricing / surface analytics described in Ingest and pricing.

The whole loop

market / broker inputs data, storage, QC modeling, pricing, decision execution, state, control research / governance

What it adds

  • The control loop. Strategy generation, portfolio risk, execution, ledger, reconciliation, and active monitoring — none of which exist today.
  • Pricing separated from forecasting. Surface fitting and greeks are current-market analytics. They are not a realized-vol forecast, and conflating them is the easiest way to think a model has edge.
  • Delayed research feeds separated from live execution feeds. The delayed feed is enough for research and sanity checks, and not enough for order placement or intraday risk.
  • State made explicit. Internal positions, orders, fills, and decision logs are first-class components rather than something recovered from the broker on demand.
  • A closed feedback loop. Backtests, replay, attribution, dashboards, and governance feed back into production changes.

Implementation order

  1. Canonical event store, reference data, QC gates.
  2. Pricing, feature generation, baseline RV forecast.
  3. One defined-risk strategy engine with explicit exits.
  4. Portfolio risk engine with hard guardrails and stress tests.
  5. OMS / execution simulator, then the broker adapter.
  6. Ledger, reconciliation, dashboards, alerts.
  7. Event replay and backtesting that run the same production logic.

Operating principles

  1. Keep delayed research data separate from current execution data.
  2. Forecast future realized volatility; do not confuse it with fitting the current implied vol surface.
  3. Every trade passes portfolio-level risk checks before execution.
  4. Preserve immutable decision logs and reconcile continuously against broker reality.
