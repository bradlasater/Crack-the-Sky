Headless box — operations outside the repo

Companion to the system handbook (docs/index.html). The repo declares what the system should be; this page records the machine state it cannot declare — secrets, the installed schedule, services, and the external accounts — and how each piece was put in place. Host: brad-headless-server, user brad-lasater, no passwordless sudo (by design; everything below runs as the user).

Installed schedule

active The box crontab is installed directly from the repo (crontab deploy/crontab — the placeholder path already matches the box user, no sed rewrite needed) and is byte-identical to deploy/crontab on main. The box.yml “Crontab drift” step fails the build if these diverge; that alarm fired on 2026-09-01 when PRs #10/#11 added rates_sync and ibkr_executions before the crontab was re-installed. Fix is always the same: pull main, re-install the crontab.

GitHub Actions self-hosted runner

active Installed 2026-09-01 to replace Buildkite. Registered to the repo as ingest-box (labels self-hosted, linux, x64 — what .github/workflows/box.yml targets). Runs as a user-level systemd unit, no sudo:

~/.config/systemd/user/actions-runner.service
  ExecStart = ~/actions-runner/run.sh        # foreground mode; runsvc.sh needs sudo
  EnvironmentFile = ~/crack-the-sky/.env # so jobs see the credentials
  Restart = always
loginctl enable-linger brad-lasater          # survives logout/reboot

Verify from anywhere: gh api repos/{owner}/{repo}/actions/runners should show ingest-box online. Accepted risk (documented in the workflow header): pushed code runs next to the market-data credentials and /data/massive — fine for a private, single-owner repo with 2FA; the keys are read-only and no brokerage access is reachable.

Healthchecks.io

active Fifteen checks, one per cron job, named massive-<job>. Jobs ping via the ping key in .env; schedules and grace periods were aligned to the crontab with scripts/setup_healthchecks.py on 2026-09-01 (without that step, auto-created checks get a default daily schedule and false-alarm over weekends on the weekday-only jobs). A notification channel (email/Slack) must exist in the Healthchecks UI or alerts go nowhere.

IBKR Flex Web Service

active Verified live 2026-09-01: token + query id authenticate, the statement generates, the period guard refuses a mislabeled date, and a no-fills day exits cleanly. The query’s saved period (“Last Business Day”) decides the statement’s contents — the 18:30 ET cron passes no --date and the job checks the statement period matches. If the token is regenerated (~yearly), only .env changes.

Removed: Buildkite

gone Repo webhook deleted 2026-09-01; no buildkite-agent unit or process exists on the box. The only remaining artifact is the subscription itself — cancelled (or cancelled separately) in the Buildkite UI, which is where billing stops. Replacement: the self-hosted runner above plus a GitHub ruleset on main (PR required; test (3.11) / test (3.12) checks required).
