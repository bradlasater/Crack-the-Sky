Documented knobs

← overview

From .env.example (no secrets). Process environment overrides the file. Do not commit .env. Where each value actually lives on the box: box operations.

Credentials and endpoints

NameRole
MASSIVE_API_KEYRequired. Query-param auth.
MASSIVE_API_BASEDefault https://api.polygon.io.
WS_DELAYED_URLDefault wss://delayed.massive.com/options.
MASSIVE_S3_ACCESS_KEY_ID
MASSIVE_S3_SECRET_ACCESS_KEY		Flat-file access keys (placeholders exit 3 on pull).
MASSIVE_S3_ENDPOINT
MASSIVE_S3_BUCKET		Flat-file endpoint and bucket (defaults https://files.massive.com / flatfiles).

Paths

NameRole
DATA_ROOTWarehouse root. Default /data/massive.
LOG_ROOTLogs. Default DATA_ROOT/logs (not the warehouse root). Settings.load in ingest/common/config.py.

Healthchecks and canary

NameRole
HEALTHCHECKS_PING_KEYPer-job checks. Without it, a dead job is silent.
HEALTHCHECKS_API_KEYManagement key used only by scripts/setup_healthchecks.py to create/update the checks. Not read at run time, and not the ping key.
HEALTHCHECKS_BASEPing root (hosted https://hc-ping.com; self-host https://<host>/ping).
DRIFT_CHECK_RScalar r for the 17:00 canary (default 0.04).
DRIFT_ALERT_WEBHOOKOptional FAIL POST. Healthchecks + exit 1 remain the alert.

Code-side knobs

Also in code, not in .env.example: MASSIVE_MAX_RPS / MASSIVE_BURST (40), MASSIVE_RATELIMIT_SHARED (1 — the token bucket is cross-process by default, so every job on the box draws on one allowance rather than one each; set 0 for the old per-process behaviour), MASSIVE_RATELIMIT_STATE (DATA_ROOT/_meta/ratelimit.json), MASSIVE_PRIORITY_RESERVE (0.35 — the fraction of the bucket reserved for snapshot_sweep; every other capture job draws at low priority and stops at this floor, which is where “everything else yields API budget to it” is actually enforced), TRADES_CONCURRENCY (8), RETAIN_DAYS (90), QUARANTINE_RETAIN_DAYS (30 — superseded re-filter output under _quarantine/, pruned on the monthly run), FLATFILE_RETAIN_DAYS (365 — only consulted with prune_raw.sh --flatfiles, which is opt-in), MIN_FREE_GB (100 on backfill), TZ_NAME (America/New_York), JOB_MAX_ATTEMPTS (3) / JOB_RETRY_BASE_S (30s, doubling, capped at 300s) — in-run retry, since cron has no backoff. Legacy HEALTHCHECKS_PING_URL is rejected.
